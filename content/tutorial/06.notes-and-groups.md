Explain design decisions with sticky notes and organize related tables with named, colored regions.

## Add a sticky note

Select **New note**, the sticky-note icon in the bottom-left canvas controls. A note appears in the
diagram. Click its text area and write a description, question, or reminder. For example:

```
Each order belongs to one customer.
Keep historical orders when reviewing retention requirements.
Confirm the deletion policy before deploying SQL.
```

Notes support plain text and line breaks. They do not render Markdown, upload attachments, or create
threaded comments. Markdown formatting is available in this tutorial and AI responses, not inside
sticky-note text.

## Move, resize, and color a note

Drag the top strip to reposition the note. Hover over or select it to reveal its color button,
delete button, and bottom-right resize handle. Drag the resize handle to change its width and
height. There are minimum and maximum sizes, so resizing stops at the limits. Longer text can scroll
within the note.

Select the color button to open the palette. Use color to distinguish questions from accepted design
decisions. Note color, content, position, and dimensions are saved with the schema. Right-click and
choose Bring to front or Send to back if the note overlaps something else.

Select the note and press Delete, or use its small × button, to remove it. Undo can recover a recent
accidental removal.

## Add and name a table group

Select **New table group**, the group icon in the canvas controls. A dashed rectangle appears with a
name field in its header. Name it for a domain, such as `Sales`, `Billing`, or `Identity`.

Move the rectangle by dragging its header outside the input. Resize it from the lower-right handle
so it surrounds the intended tables. The header color button opens a palette. Use **Send to back**
if the group obscures another object.

A group is a visual region. It does not create a database schema or namespace, change table names,
or grant permissions. Tables are not nested children of the group: dragging a group does not move
the tables inside it. Move tables separately to rearrange the domain.

## Remove a group

Use the header's × button or select the group and press Delete. The tables and relationships remain.
A group is an independent annotation, so removing it does not remove its contents.

## Sharing, saving, and SQL

Notes and groups appear in the shared read-only canvas and in team diagrams. Viewers see their text
and colors but cannot edit them. They are included in schema versions and schema changes; they do
not generate SQL statements. Follow [normal saving rules](/tutorial/saving-and-history) after making
changes.
