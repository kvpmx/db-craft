Build tables, choose database-specific field types, set constraints, reorder fields, and keep your
schema readable.

## Add and rename tables

Open the **Tables** tab and choose **New table**. Each new table has a generated name, a color, and
an `id` field marked as a primary key. Its initial field type depends on the database engine. Review
that type for your design, especially before SQL export.

Hover over a table's sidebar heading and select the pencil. Type the new name and press Enter or
select the check mark. Empty names are not applied. Select the heading to expand or collapse the
field editor. Only one table's field section is expanded at a time.

::tutorial-media{src='/tutorial/media/table-fields.png' alt='Expanded customers table showing field names, types, and options'}
::

Table names become SQL identifiers. Prefer consistent, descriptive names such as `customers`,
`orders`, and `order_items`. Avoid duplicate names within a diagram. Drag table headings in the
sidebar to reorder the list; move canvas table headers to arrange the visual layout. These are
separate operations.

## Add and edit fields

1. Expand the table in the sidebar.
2. Select **Add field**. The new row starts with a generated field name and the first available type
   for the current engine.
3. Replace the field name directly in its input.
4. Open its type selector, search for a type, and choose a result. The list is specific to the
   project's database.
5. Open the field's options button to set constraints.

Edits update the canvas immediately. They still need a personal Save or a successful team autosave.
Drag a field's left-hand handle to reorder columns within the table. This order is reflected in the
diagram and SQL output.

The type picker selects predefined base types. It does not include separate controls for length,
precision, enum values, defaults, or arbitrary SQL expressions. For types such as `varchar` and
`decimal`, the SQL generator applies default dimensions; see
[SQL export and database types](/tutorial/sql-export).

## Field constraints

| Option         | Meaning                                   | How the editor handles it                                                                                |
| -------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Primary key    | Identifies rows                           | Unavailable while Nullable is enabled. A primary key is treated as non-nullable and unique.              |
| Nullable       | Allows a missing value                    | Disabled for primary-key and auto-increment fields. Turn those options off first if appropriate.         |
| Unique         | Prevents duplicate values                 | Disabled when Primary key is selected because the primary key already implies uniqueness.                |
| Auto increment | Requests an automatically generated value | Requires Primary key and a non-nullable field. Choose a suitable database type and review generated SQL. |

::tutorial-media{src='/tutorial/media/field-options.png' alt='Field options menu with primary key, nullable, unique, and auto increment'}
::

For a customer email, choose `varchar`, leave Primary key off, and select Unique. For a numeric
generated identifier, choose an appropriate integer type, keep Primary key enabled, and enable Auto
increment if needed for your dialect. The type and checkbox combination still needs to be valid in
your target database; the editor is not a full database validator.

Marking several fields as primary keys does not replace reviewing the generated compound-key SQL.
The current generators have dialect-specific limitations, so check the result in a database tool
before using it.

## Colors, search, and locating a table

The color picker at the bottom of an expanded table changes its header color. Choose a color from
the palette. Color is a visual aid; it does not affect SQL or access permissions.

The search box at the bottom of the Tables panel searches **table names**, ignoring case. Matching
text is highlighted. It is not a global field-name search. Hover over a table heading and select the
fit icon to center that table on the canvas. Select the small expand icon on a canvas table’s header
to open its matching sidebar section. The key icon identifies a primary-key field, and a question
mark after a field’s type indicates that it is nullable.

## Remove fields and tables

Choose **Remove** in a field's options menu to delete it. Relationships connected to that field are
removed too. To remove a whole table, hover over its sidebar heading and use the trash icon. All
relationships connected to that table are also removed.

These actions do not offer a confirmation dialog. Use Ctrl+Z promptly if you make a mistake, or
restore a deliberate checkpoint from [version history](/tutorial/saving-and-history). Removing a
field from a diagram does not issue a DROP COLUMN command against a live database.
