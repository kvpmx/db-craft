Keep changes persistent, undo recent edits, and create named checkpoints you can restore later.

## Save a personal diagram

Personal projects use the **Save** button in the editor header. An unsaved diagram shows a
warning-colored border and cloud indicator. Hover over the button to see whether changes are saved
and, for saved work, the last modification time.

Select Save after changing table definitions, relationships, notes, groups, layout, or the project
name. The save operation persists the diagram and updates its thumbnail. SQL export does not save a
diagram. Creating a version snapshot also does not replace saving the current personal project.

If you navigate away with unsaved changes, the app asks whether to leave. Closing or refreshing the
tab may also show the browser's unsaved-changes warning. Stay on the page and save if you want to
keep those edits. Undo history is not an offline backup.

## Autosave in teams

Team diagrams start collaboration when opened. Once ready, changes synchronize with other
participants and save automatically. The header indicates **Saving**, **Saved**, or a retry action
on error. A live connection and a completed save are separate signals: check both when finishing
work.

If saving fails, keep the tab open, restore the connection, and use the retry/save action. When
leaving a team diagram, the app attempts to save pending changes before asking about unsaved work.
See [Live collaboration](/tutorial/collaboration) for connection states and recovery.

## Undo and redo

Use **Ctrl+Z** to undo and **Ctrl+Y** to redo when you are working on the canvas. These shortcuts
are suppressed while a text input, textarea, select, or editable text area has focus so they do not
compete with ordinary typing.

Personal diagram history keeps up to 20 recent state changes in the current session. Team undo uses
your local collaboration history; it is intended to undo your changes while preserving other
people's edits. Undo is not a permanent list of every action, and opening the diagram in another
session does not restore that local history.

The current shortcuts are Control-based, including on macOS; Command+Z is not registered as a canvas
shortcut. Use version checkpoints for durable recovery instead of relying on session undo.

## Commit a version

1. Open the history button in the editor header. It is available to users with edit permission.
2. Enter a nonempty message describing the checkpoint, such as `Customer and order keys reviewed`.
3. Select **Commit version**. The current schema is copied into a saved snapshot.
4. Check the timeline for the new entry. Entries show the commit message and author; hover to see
   the date.

::tutorial-media{src='/tutorial/media/version-history.png' alt='Version history showing a named checkpoint and rollback control'}
::

A version stores the schema: tables, fields, relations, notes, groups, and their layout. It does not
checkpoint account settings, team membership, AI chat, or the project title and visibility. Give
versions meaningful messages so you can choose the right snapshot later.

## Roll back to a checkpoint

Select an entry in the timeline, then choose **Rollback to selected** and confirm the prompt. The
selected schema becomes the working diagram, and the history panel closes. There is no side-by-side
diff preview in the current history interface.

For a personal project, select Save after verifying the restored diagram. In a team, the restore is
a shared schema change and will synchronize and autosave. Tell teammates before restoring a shared
diagram because it can replace the schema they are currently editing.

Before rollback, commit the current design if you might need to return to it. Rollback does not
recover deleted projects or teams and does not run rollback SQL against a database.
