Create a shared workspace, invite members with email-bound codes, manage roles, and administer a
team.

## Create and open a team

Select **Create team** in the main sidebar, enter a team name, and submit. The new team opens and
appears in your team list. Its creator is an admin. Select the team in the sidebar to return to its
projects later.

Admins and editors can use **New project** on the team page. Team diagrams are created private and
inherit access from active team membership. Project search, duplicate, and delete work in the team
workspace just as they do in personal Projects, subject to your role.

## Roles at a glance

| Capability                                        | Admin | Editor | Viewer |
| ------------------------------------------------- | ----- | ------ | ------ |
| Open team diagrams and inspect schemas            | Yes   | Yes    | Yes    |
| See other connected participants                  | Yes   | Yes    | Yes    |
| Create, edit, duplicate, and delete team diagrams | Yes   | Yes    | No     |
| Apply AI changes, commit versions, and roll back  | Yes   | Yes    | No     |
| Open SQL export in the authenticated editor       | Yes   | Yes    | Yes    |
| Rename the team, invite members, and manage roles | Yes   | No     | No     |
| Delete the team                                   | Yes   | No     | No     |

A public sharing link is different from a team invitation. It gives read-only access to a public
personal diagram and does not add anyone to a team.

## Invite people

1. Open the team page and select **Team settings**. Only admins see this entry.
2. In **Create invite code**, add one or more email addresses. Press Enter or use a separator to
   commit each address as a tag. Remove an incorrect tag and enter it again.
3. Choose the intended role. The form initially offers Viewer; select Editor if people need to
   change schemas.
4. Select **Generate invite code**. The code appears below the form, and pending members appear in
   the member list.
5. Select **Copy** and send the code to the intended people through your usual communication
   channel.

DB Craft generates a code; this interface does not automatically send invitation email. A code can
cover multiple addresses in the same invitation batch, but acceptance is checked against the
signed-in account email. Duplicate addresses are normalized and existing members/invitees are
skipped; a request containing only existing addresses returns an error.

## Join a team

Sign in with the email address the admin invited. Select **Join team** in the main sidebar, enter
the code, and wait for its preview. Codes are trimmed and normalized to uppercase. A valid matching
invitation shows the team name and role. Review them, then select Join team.

The join button stays disabled while checking the code or if it is invalid, expired, or belongs to
another email address. Ask the admin for the current code if it cannot be found. If the email does
not match, sign in with the invited account or ask the admin to invite the correct address.

## Manage members and codes

The member table shows each person's email, role, and Pending or Active status. Pending entries have
controls to copy their code and regenerate it. Regenerating changes the code for that invitation;
share the replacement with everyone still pending in that batch. It does not itself extend an
expired invitation's expiration.

For active non-admin members, use the role dropdown to change access. The interface lets you promote
them to admin, editor, or viewer. Admin rows do not expose the same role-change or removal controls,
so choose admin access deliberately. Remove a non-admin member or pending invitee using **Remove**
to withdraw their membership or pending access.

## Rename or delete a team

In Team settings, change **Team name** and select **Save**. The save action requires a nonempty,
changed name.

The **Delete team** section asks for confirmation before deleting the team. Deletion removes its
projects and related team data. Export anything you need to retain before confirming; a schema
version is stored within its project and is not a separate backup of a deleted team. After deletion,
the app returns to personal Projects.
