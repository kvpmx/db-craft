Ask questions about your diagram, generate a starting schema, and review proposed changes before
applying them.

## Open the assistant

Select **AI** in the editor's sidebar toolbar. You need edit access: the tab is not shown to team
viewers or on public share pages. The assistant receives the project's database type and current
schema with your request, so you can ask questions about your actual diagram.

An empty conversation offers suggested prompts for describing the diagram, adding a table, and
reviewing the design. Selecting a suggestion fills the composer; review or edit it and send when
ready.

::

## Ask a useful question

Be specific about the desired outcome, entities, constraints, and database assumptions. For example:

```
Explain how customers and orders are related in this diagram.
Identify nullable foreign keys and missing uniqueness constraints.
Do not change the schema yet.
```

For a new feature:

```
Add products and order_items to this PostgreSQL shop schema.
An order has many order_items. Each item references one product.
Include quantity and unit_price. Keep existing customers and orders.
```

For a new diagram, describe the entities and relationships you want. For an existing diagram,
explicitly name what should be preserved. The assistant can answer in formatted text with lists,
tables, and code blocks, or return a proposed schema change.

## Send, stop, and continue

Press **Enter** or select the send button to submit a message. Press **Shift+Enter** for a new line.
Empty messages cannot be sent. During generation, the interface displays a thinking or
proposal-generation indicator and replaces the send action with **Stop**.

Select Stop to interrupt the response. You can then send a more focused follow-up. Stopping does not
roll back changes you already applied, and a partial answer may not contain a complete proposal. The
message list scrolls as new content arrives.

## Review a proposal

A proposal appears in a separate **Proposed schema changes** card with a summary and two actions:

- **Apply** installs the proposed schema in the editor. The card then shows that it was applied.
- **Discard** dismisses the proposal without changing the diagram. The card shows that it was
  discarded.

Ordinary assistant text does not change the schema. Read the summary, check names, field types,
keys, and relationships, and compare the canvas after applying. The AI can produce mistakes or
assumptions that do not fit your database.

> Applying a proposal installs the schema snapshot prepared when it was generated. If you or a
> teammate have edited the diagram since then, request a fresh proposal before applying it so newer
> work is not replaced by an older snapshot.

Commit a [schema version](/tutorial/saving-and-history) before large AI changes. Undo or rollback
can recover the previous design. Applying a proposal changes the working diagram; personal projects
still need Save, and team changes follow autosave and synchronization.

## Conversation history and clearing

Conversation history is saved per user and per project, including applied/discarded proposal state,
and is loaded when you return to that project's AI panel. Teammates have their own conversations;
schema changes you apply are shared through the team diagram.

**Clear chat** removes your stored messages and proposal history for this project. It does not
revert the schema or delete the diagram. The control is disabled while a response is generating.
Save important explanations elsewhere before clearing the conversation; there is no chat restore
screen.

## Errors and availability

If the request fails, an error message appears in the conversation. Check your connection and edit
access, then try a shorter or more specific request. Provider limits or unavailable service
configuration can also prevent responses. Your manual diagram tools remain usable when AI is
unavailable. Never assume a failed response applied a change: inspect the diagram and the proposal
card.
