Preview, copy, and download SQL for six database engines, and understand what the current exporter
includes.

## Open and download SQL

Open a diagram in the authenticated editor and select **Export as SQL** in the header. This action
is visible at desktop widths; widen the browser if it is missing. The dialog displays a read-only
code editor with SQL generated from the current working schema and the project's engine.

Use the copy button in the code area to copy the complete script to the clipboard, or select
**Download as file** to download `<project name>.sql`. Cancel or close the dialog when finished.
Copying requires browser clipboard access; downloading is an alternative if access is blocked.

::tutorial-media{src='/tutorial/media/sql-export.png' alt='SQL export dialog showing generated customer and order definitions'}
::

SQL is generated from the current in-memory diagram, which can include unsaved edits. Export is not
a save or a migration execution. Save the diagram separately and review the script in your database
tools before running it.

## Supported engines

Choose the database engine when creating the project. Both the field picker and SQL generator use
that choice. The following are examples, not the full type lists: open the searchable field selector
to inspect all available types for the chosen engine.

| Engine     | Examples of available types                                                         |
| ---------- | ----------------------------------------------------------------------------------- |
| MySQL      | `int`, `bigint`, `varchar`, `decimal`, `datetime`, `json`, `enum`, `geometry`       |
| PostgreSQL | `integer`, `serial`, `text`, `uuid`, `boolean`, `jsonb`, `timestamptz`, range types |
| SQL Server | `int`, `nvarchar`, `datetime2`, `uniqueidentifier`, `bit`, `xml`, `geography`       |
| SQLite     | `integer`, `real`, `text`, `blob`, `numeric`, `boolean`, `datetime`                 |
| MariaDB    | `int`, `varchar`, `decimal`, `json`, `uuid`, `inet4`, `inet6`                       |
| Oracle     | `number`, `varchar2`, `nvarchar2`, `timestamp`, `clob`, `raw`, `xmltype`            |

Some listed types or features depend on your database version, require extra type definitions, or
need additional parameters. Selecting a type does not validate it against an actual database server.
There is no engine conversion control for an existing diagram.

## What the export includes

The generator creates table definitions from names, field order, field types, primary keys,
nullability, uniqueness, and auto-increment settings. Relations generate foreign-key definitions
from their source and target fields, using a custom constraint name or a generated default. The
current SQLite generator also emits separate ALTER TABLE constraint statements; adapt those foreign
keys into CREATE TABLE definitions before using them in SQLite.

The export does not include rows of data, canvas positions, colors, notes, groups, team membership,
AI conversation, or version history. It produces a creation script rather than a difference between
your diagram and an existing database. Changing a diagram does not generate a complete migration
plan.

## Type dimensions and constraints

The manual type picker selects base types. The current normalizer adds defaults for certain types:

| Base type                                      | Generated default     |
| ---------------------------------------------- | --------------------- |
| `varchar`, `varchar2`, `nvarchar`, `nvarchar2` | Length 255            |
| `char`, `nchar`                                | Length 1              |
| `binary`, `varbinary`                          | Length 255            |
| `decimal`, `numeric`, `dec`, `fixed`           | Precision 10, scale 2 |

If your application needs different dimensions, defaults, checks, enum values, indexes, or
specialized database options, adapt the downloaded SQL in your database tooling. The editor does not
provide controls for all of those features.

A source field becomes the foreign key referencing the target field. Cardinality labels alone do not
create a uniqueness constraint, change nullability, or create a many-to-many junction table. Review
types and keys explicitly. Compound primary keys and engine-specific generated-value syntax also
require checking the generated result.

## Cascading behavior

Foreign-key actions are chosen by each generator and have no editable cascade controls in the
current form. MySQL, MariaDB, and SQLite emit `ON DELETE CASCADE` and `ON UPDATE RESTRICT`.
PostgreSQL, SQL Server, and Oracle emit `ON DELETE CASCADE` without an explicit update action.

Deleting a referenced row can therefore delete related rows if you run these definitions as
generated. Review these clauses for your application and edit the script before applying it. The
source/target field selectors do not change cascade policies.

## Current boundaries

The current UI does not offer direct database connections, an SQL file import flow, reverse
engineering a live database, query execution, or a user-facing PNG export button. Project thumbnails
are generated internally when saving personal diagrams. Use SQL download for the implemented export
workflow and public sharing for a browsable diagram.

The AI assistant can help discuss or propose a schema, but it is not a verified SQL importer or
database execution tool. Always inspect the resulting diagram and script.
