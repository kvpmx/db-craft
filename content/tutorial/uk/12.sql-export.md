Переглядайте, копіюйте й завантажуйте SQL для шести рушіїв і розумійте, що входить до поточного
експорту.

## Відкрийте й завантажте SQL

Відкрийте діаграму в автентифікованому редакторі й оберіть **Експортувати як SQL** у заголовку. Цю
дію видно на ширині робочого столу; якщо її немає, розширте браузер. Діалог показує редактор коду
лише для читання з SQL, згенерованим із поточної робочої схеми і рушія проєкту.

Кнопка копіювання в області коду копіює весь скрипт у буфер обміну, а **Завантажити як файл**
завантажує `<назва проєкту>.sql`. Закінчивши, скасуйте або закрийте діалог. Копіювання потребує
доступу браузера до буфера; якщо доступ заблоковано, завантаження є альтернативою.

::

SQL генерується з поточної діаграми в пам’яті, яка може містити незбережені правки. Експорт — це не
збереження і не виконання міграції. Збережіть діаграму окремо і перегляньте скрипт у своїх
інструментах бази, перш ніж запускати його.

## Підтримувані рушії

Рушій бази обирають під час створення проєкту. І селектор полів, і генератор SQL використовують цей
вибір. Нижче приклади, а не повні списки типів: відкрийте селектор із пошуком, щоб побачити всі типи
обраного рушія.

| Рушій      | Приклади доступних типів                                                            |
| ---------- | ----------------------------------------------------------------------------------- |
| MySQL      | `int`, `bigint`, `varchar`, `decimal`, `datetime`, `json`, `enum`, `geometry`       |
| PostgreSQL | `integer`, `serial`, `text`, `uuid`, `boolean`, `jsonb`, `timestamptz`, range types |
| SQL Server | `int`, `nvarchar`, `datetime2`, `uniqueidentifier`, `bit`, `xml`, `geography`       |
| SQLite     | `integer`, `real`, `text`, `blob`, `numeric`, `boolean`, `datetime`                 |
| MariaDB    | `int`, `varchar`, `decimal`, `json`, `uuid`, `inet4`, `inet6`                       |
| Oracle     | `number`, `varchar2`, `nvarchar2`, `timestamp`, `clob`, `raw`, `xmltype`            |

Деякі перелічені типи або можливості залежать від версії бази, потребують додаткових визначень типів
або параметрів. Вибір типу не перевіряє його на реальному сервері. Для наявної діаграми немає
перетворення рушія.

## Що входить до експорту

Генератор створює визначення таблиць із назв, порядку полів, типів, первинних ключів, допустимості
NULL, унікальності й автоінкремента. Зв’язки породжують визначення зовнішніх ключів із вихідного й
цільового полів, із власною назвою обмеження або згенерованою типовою. Поточний генератор SQLite
також виводить окремі оператори ALTER TABLE; перед використанням у SQLite перенесіть ці зовнішні
ключі в визначення CREATE TABLE.

Експорт не містить рядків даних, положень на полотні, кольорів, нотаток, груп, членства в команді,
розмови зі ШІ чи історії версій. Це скрипт створення, а не різниця між діаграмою і наявною базою.
Зміна діаграми не породжує повного плану міграції.

## Розміри типів і обмеження

Ручний селектор типу обирає базові типи. Поточний нормалізатор додає типові значення для деяких
типів:

| Базовий тип                                    | Типове значення        |
| ---------------------------------------------- | ---------------------- |
| `varchar`, `varchar2`, `nvarchar`, `nvarchar2` | Довжина 255            |
| `char`, `nchar`                                | Довжина 1              |
| `binary`, `varbinary`                          | Довжина 255            |
| `decimal`, `numeric`, `dec`, `fixed`           | Точність 10, масштаб 2 |

Якщо застосунку потрібні інші розміри, значення за замовчуванням, перевірки, значення enum, індекси
чи спеціальні опції бази, адаптуйте завантажений SQL у своїх інструментах. Редактор не дає елементів
керування для всіх цих можливостей.

Вихідне поле стає зовнішнім ключем, що посилається на цільове. Самі підписи кардинальності не
створюють обмеження унікальності, не змінюють допустимість NULL і не створюють проміжну таблицю
багато-до-багатьох. Типи й ключі перевіряйте явно. Складені первинні ключі й синтаксис згенерованих
значень конкретного рушія також треба звірити з результатом.

## Каскадна поведінка

Дії зовнішнього ключа обирає кожен генератор; у поточній формі немає редагованих елементів каскаду.
MySQL, MariaDB і SQLite виводять `ON DELETE CASCADE` і `ON UPDATE RESTRICT`. PostgreSQL, SQL Server
і Oracle виводять `ON DELETE CASCADE` без явної дії оновлення.

Видалення рядка, на який є посилання, може тому видалити пов’язані рядки, якщо запустити ці
визначення як є. Перевірте ці конструкції для свого застосунку і відредагуйте скрипт перед
застосуванням. Селектори вихідного й цільового полів політику каскаду не змінюють.

## Поточні межі

Поточний інтерфейс не пропонує прямого з’єднання з базою, імпорту SQL-файлу, зворотного проєктування
живої бази, виконання запитів або кнопки експорту PNG для користувача. Мініатюри проєктів
створюються всередині під час збереження особистих діаграм. Для реалізованого експорту
використовуйте завантаження SQL, а для діаграми, яку можна переглядати, — публічне поширення.

ШІ-асистент може допомогти обговорити або запропонувати схему, але він не є перевіреним імпортером
SQL і не виконує команди в базі. Завжди оглядайте отриману діаграму і скрипт.
