Edit the same team diagram together, see who is present, and understand connection and save status.

## Start a shared session

Join a team and open one of its diagrams. Other active members can open that same project from their
own accounts. Collaboration initializes automatically for team diagrams, including viewers. Personal
diagrams and anonymous public share pages do not start a live editing session.

The editor waits for the initial shared state before enabling team edits. If editing controls seem
unavailable just after opening, allow the connection to finish and check your role. Admins and
editors can change the diagram; viewers can inspect it.

## Presence and cursors

The header displays participant avatars or initials with identifying colors. Hover over an avatar to
see the person's name. If someone has several tabs open, the avatar list groups them by user.
Colored cursors on the canvas show where participants are pointing.

Cursors are positioned in diagram coordinates so they remain aligned when people have different zoom
levels. Moving the pointer out of the canvas or leaving the window clears your active canvas cursor.
Presence indicates someone is connected, not that their latest edits have already been saved.

## What is synchronized

Team edits include table and field data, relations, note text and size, group names and size, object
positions and stacking order, and the diagram name. Dragging and resizing send updates during the
interaction. Each person controls their own viewport and sidebar, so one person's panning does not
force everyone else to follow.

Changes are merged through the shared document. Editing different fields or tables together is the
easiest workflow. When two people change the same property, the final merged value can supersede one
person's intention; check the resulting schema together. A deleted table or field also removes
relationships that depend on it.

AI conversations remain personal, but **applying an AI proposal** changes the shared schema.
Restoring a version also changes the shared schema. Coordinate these larger operations and request a
new AI proposal if the diagram has changed since a proposal was generated.

## Connection states

| Status     | Meaning and next step                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| Connecting | The session is joining and loading shared state. Wait before making edits.                             |
| Live       | The collaboration connection is active. Check Saved separately before closing.                         |
| Offline    | The realtime connection is unavailable. Keep the tab open and restore connectivity.                    |
| Error      | A connection or persistence operation failed. Check access/connectivity and use the retry/save action. |

Hover over the small status dot to read its status text. Green represents Live; the other states use
an amber indicator. Saving/Saved in the save control reports persistence rather than merely the
connection state.

## Recover from interruptions

Keep the page open if you have unsaved work. Reconnect and allow synchronization to resume, then use
Retry save if shown. Check that the save indicator reaches Saved before leaving. Pending changes
held in the current page are not a guaranteed offline backup after a refresh or browser closure.

If your membership or role changed, ask a team admin to verify your access. Do not work around a
disabled editor by opening a public link: public links remain read-only. Use deliberate
[version checkpoints](/tutorial/saving-and-history) for important milestones, and review the canvas
after reconnecting.
