Create, find, duplicate, rename, and remove diagrams, and understand who can access each project.

## Personal and team workspaces

**Projects** in the main sidebar lists your personal diagrams. Select a team name below it to see
that team's diagrams. Each card shows the name, database engine, preview when available, and how
recently it was modified. Hover over the modification time for the full date and time. Select a card
to open the editor.

The search box filters project names in the current workspace without regard to letter case. Clear
it to see all projects again. An empty result can mean there are no matching names, not that your
work was deleted. Check whether you are viewing Projects or a team.

## Create a diagram

Select **New project**, enter a nonempty name, choose a database engine, and select **Create
diagram**. Personal projects also show a visibility choice. The selected database determines field
types and the export dialect; there is currently no database-engine switch in the editor.

| Workspace or visibility  | Who can open it?                                                          | Who can edit it?        |
| ------------------------ | ------------------------------------------------------------------------- | ----------------------- |
| Private personal project | The owner through their account                                           | The owner               |
| Public personal project  | The owner in the editor; anyone with the public link in the shared viewer | The owner               |
| Team project             | Active team members through their accounts                                | Team admins and editors |

Team projects are created as private. Choose the intended workspace before creating the diagram: the
interface does not offer moving an existing personal project to a team. Public access is described
in [Sharing diagrams](/tutorial/sharing).

## Rename a diagram

Open the diagram on a desktop-width screen. Double-click the name in the center of the header, enter
a new name, and select the check mark. A blank name cannot be confirmed. The database icon beside
the name identifies its engine. Save your changes in personal projects; team changes save
automatically once collaboration is ready.

Renaming changes the project title and the filename used by future SQL downloads. It does not rename
tables. The centered title is hidden on small screens, so widen the window to rename it.

## Duplicate a project

On the project card, open the three-dot menu and select **Duplicate**. The new copy gets a name
ending in ` (Copy)` and keeps the source schema, database engine, visibility, and workspace. Open
the copy from the list to work independently.

Use a duplicate to explore an alternative design without changing the original. A duplicate is a
separate project; version history and your AI conversation are not copied along with the schema. In
teams, the menu is available to admins and editors.

## Delete a project

Choose **Delete** from the card's three-dot menu. The current project menu performs this action
directly; there is no project trash or restore screen. Download needed SQL or make a duplicate
before deleting a diagram you may need again. Removing a project also makes its public share link
unavailable.

Deleting a table inside an editor is a different action: it changes that diagram's schema and can be
covered by undo or an earlier schema version. See
[Saving and version history](/tutorial/saving-and-history).

## Preview images and saving

Personal saves update the project's diagram thumbnail as well as saving the schema. A placeholder
appears until a preview is available. A preview is a navigation aid, not a separate exported image,
and should not be used to decide whether the latest changes were saved. Check the save indicator in
the editor.
