Connect fields, edit foreign-key names and endpoints, and describe cardinality with labels and
crow's-foot markers.

## Understand source and target

A relationship connects a field in one table to a field in another. In generated SQL, the **source
field is the foreign key**, and it references the **target field**. For example,
`orders.customer_id` is the source and `customers.id` is the target. The target should be a suitable
primary or unique key with a compatible type.

Do not infer the direction from where tables sit on the canvas. Moving tables changes the line
routing, not which column holds the foreign key. Self-referencing relationships within the same
table are currently rejected by both the canvas and relation form.

## Create a relationship using the form

1. Create at least two tables with the fields you need.
2. Open the **Relations** tab and select **New relation**.
3. Enter a constraint name if you want to control the SQL name, or leave it blank to use the
   generated default.
4. Choose the source table and field, then the target table and field. Recheck the selected field
   after changing a table.
5. Choose the cardinality at both ends.
6. Save the form. The relation appears in the list and on the canvas.

::tutorial-media{src='/tutorial/media/relationship-form.png' alt='Relationship form linking orders.customer_id to customers.id'}
::

Constraint names are normalized to suitable identifier characters. The generated default is based on
the selected tables and fields. Use meaningful names such as `fk_orders_customer` when a schema
contains several similar links.

## Create a relationship on the canvas

Select the source table on the canvas to reveal its connection handles. Drag a small connection
handle next to a field to a handle on a field in another table. Start at the foreign-key field and
finish at the referenced field. A new line is created when you complete a valid connection. Lines
automatically change their left/right attachment as tables move.

New connections start with **One** at the source and **Zero or many** at the target. These defaults
may not match your design. For the orders-to-customers foreign key, set the orders end to Zero or
many and the customers end to One and only one if that is your intended business rule.

## Cardinality reference

Each endpoint has its own setting. The compact label on the line shows source notation, a colon, and
target notation. Markers at the endpoints visualize the same choices.

| Choice           | Notation | Meaning                                             |
| ---------------- | -------- | --------------------------------------------------- |
| Zero or one      | `0..1`   | An optional single association                      |
| Many             | `*`      | Multiple associations, without specifying a minimum |
| One              | `1`      | One association                                     |
| One and only one | `1..1`   | Exactly one, explicitly mandatory                   |
| Zero or many     | `0..*`   | No associated rows or multiple rows                 |
| One or many      | `1..*`   | At least one associated row                         |

Click the label on an editable relationship to change **Source end** and **Target end** directly in
the popover. Alternatively, edit the relation through the Relations panel.

Cardinality describes your model visually. It does not automatically change Nullable or Unique on
fields, add junction tables, or enforce row counts in the generated database. For many-to-many
designs, model the junction table and its foreign keys yourself.

## Find, edit, and delete relations

The Relations panel includes search and a list of connections. Search matches the relation name and
connected table/field names. Select a row to highlight the line. Use its Fit to screen action to
focus the connected tables. Use the edit action to reopen the form and change its name, endpoints,
or cardinality. Use the row's delete action to remove it.

You can also select a line on the canvas and press Delete. Deleting a relation leaves its tables and
fields in place. Deleting a connected table or field removes the relation automatically.

## Show or hide cardinality

Open your profile menu, choose **Settings**, and select **Diagram settings**. Toggle **Show relation
cardinality** and select **Save**. This affects the display of labels and markers; the relationship
and its saved cardinality still exist. If labels are hidden, use the Relations panel to edit them.

Review [SQL export](/tutorial/sql-export) before using foreign-key output: cascading behavior is
generated by the dialect and is not configurable through the relationship form.
